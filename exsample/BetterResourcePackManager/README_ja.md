# BetterResourcePackManager Windows v20（実機未検証）

Minecraft Windows 1.26.60.5 専用。v19では座標更新530件が終了した後、カメラ描画の直後にMinecraft本体のRVA `0x6EC9DB2` でアクセス違反が観測されました。命令は仮想関数表からの参照で、RAXがゼロでした。障害位置と更新順序は確認できましたが、参照が失効した原因までは未確定です。

v20は追加更新の範囲を縮小します。ModからのAppPlatform停止・復帰通知、停止時のセッション判定フック、モデル全体のリロード、クライアント資源の再通知を削除しました。通常のリロードが終わった後にこれらを繰り返し、描画中のモデル参照を再構築する経路を避けます。

残す追加処理は、描画タスクの待機、BlockGraphics更新、同じ件数の既存マテリアルUV更新、カメラ側の再登録です。ブロックの登録情報や共有マテリアルの所有権は変更しません。`platform_cycles`、`suspend_gate_overrides`、`geometry_reloaded`、`client_definitions_reloaded` はこの版では0になります。

ゲーム本来のリロード画面と、前の読み込みが終わるまで適用を待つv19の処理は継続します。画面を省いたv18でもクラッシュしているため、画面の削除だけを解決策とはしていません。アトラス・ローダーの完了、通常画面のフレーム完了、更新要求と各参照の一致を確認して追加更新を開始します。決め打ちの秒数待機はありません。

Minecraftを完全終了してDLLを交換してください。ログ先頭は `adapter v20 block material candidate` です。実機確認が必要なのは、パックを変更してすぐ設定を閉じた際のクラッシュ、カスタムブロックの新旧配置、プレイヤーモデル、外部サーバー接続維持、A→B→A切替です。

ログは `Documents/PEXData/BetterResourcePackManager/` です。`mode_remote_block_material_only` または `mode_local_block_material_only` が新しい追加更新の経路です。`custom_uv_result` は更新・除外件数を即時記録します。例外ログには取得可能な障害モジュールとCPUレジスターを残し、今回の障害で使われたR12/R15も追加しました。例外が記録されても、それだけで未処理クラッシュとは断定できません。

UV更新は同じバリエーション数のデータに限定し、件数変更・特殊レイヤー・名前や参照の不一致は除外します。モデルの手動リロードを外した影響を含め、ゲーム内の正常表示・クラッシュ解消は未確認です。ビルドと自動テストの成功は実機検証とは別です。
