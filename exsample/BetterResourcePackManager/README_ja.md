# BetterResourcePackManager Windows v19（実機未検証）

Minecraft Windows 1.26.60.5 専用。v18の「パック変更後すぐ設定を閉じると落ちるが、設定画面で読み込みを待つと落ちない」という報告への対策候補です。

従来はゲームのリロード画面への遷移を省き、適用コールバックを同期実行していました。v19ではこの省略処理を削除しました。ゲーム本来のリロード画面に、コールバックの保持・実行・完了待ちを任せます。

追加の描画更新は、アトラスの完了通知とローダーの完了条件に加え、リロード画面が閉じてHUDまたはポーズ画面に戻り、元のゲームフレームが一度最後まで実行された後に行います。次のフレームでも同じ更新要求・ローダー・アトラスと完了条件を再確認します。決め打ちの秒数待機は追加していません。

v18のカスタムブロックUV更新、接続維持用の停止通知ゲート、モデル更新、診断ログは継続します。v18の例外はカメラ更新の終了後にMinecraft本体以外で観測されましたが、障害モジュールとスタックが未特定のため、この対策でクラッシュが解消するかは実機未確認です。ネイティブのリロード画面を戻すことによる外部サーバー接続・画面遷移も確認が必要です。

Minecraftを完全終了してDLLを交換してください。先頭表示は `adapter v19 native progress candidate` です。

確認対象は、パック変更後すぐ設定を閉じる操作、A→B→Aの切替、カスタムブロックの新旧配置、モデル表示、外部サーバー接続維持です。

ログは `Documents/PEXData/BetterResourcePackManager/` に出力します。`native_reload_screen_navigation` は本来のリロード画面への遷移、`refresh_wait_native_reload_screen` は追加更新の待機、`native_reload_world_frame_completed` は通常画面のフレーム完了です。`custom_uv_result` は更新・除外件数を即時記録し、クラッシュが2秒ごとの通常ログより早くても結果を残します。例外ログに取得可能なモジュール名とCPUレジスターも追加しました。例外が記録されても、それだけで未処理クラッシュとは断定できません。

UV更新は同じバリエーション数のデータに限定しています。件数変更・特殊レイヤー・名前や参照が一致しないデータは除外します。Windowsビルドと自動テストの成功は、ゲーム内検証とは別です。
