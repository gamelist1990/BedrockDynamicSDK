# AutoMine

Baritone（Java版）風の自動採掘クライアントMod。対象ブロックを指定すると、付近を探索して歩いて近づき、最適なツールに持ち替えて掘り続ける。

## 使い方

| コマンド | 動作 |
| --- | --- |
| `/mine <ブロックID>` | 採掘開始（例: `/mine iron_ore`、`/mine stone`、`/mine oak_log`） |
| `/mine status` | 現在の状態をチャットに表示 |
| `/mine path` | 経路表示の ON/OFF 切替 |
| `/mine stop` | 停止（合成入力は全て解放される） |

ブロックIDはローカル名（`minecraft:` なし）で完全一致。見つからない場合は約2秒間隔で再探索するので、歩き回れば新しいエリアでも掘り始める。

コマンドはクライアントの CommandRegistry に通常登録される（`NativeMessageCommands`、引数は message 型を `block` とラベル付けした任意引数）ため、入力中に補完候補として `/mine` が出て、そのままローカル実行される。コマンドの受け取りはこの登録経路のみ（パケット捕捉は行わない）。なお引数なしの `/mine` 単体はクライアントがローカル実行に回さないことがある（実機確認済み）ため、状態確認は `/mine status` を使うこと。

## 仕組み

- **探索**: プレイヤー中心に半径（既定24、設定で変更可）を走査し、最も近い対象ブロックへ向かう。掘れない場所（到達不能・タイムアウト）はブラックリストして次を探す。
- **移動**: ゲーム本来の入力経路だけで歩く。キーはネイティブキーボード経路、視点と攻撃は実イベントと同じ形で `MouseDevice::feed` へ流す（SDKのマウスAPI・回転コンポーネント書込み・OS合成入力はこのクライアントでは視点/破壊に効かないことを実測で確認済み）。サーバーからは通常のプレイヤー操作に見える。段差は自動ジャンプ、正面が塞がれていれば掘り抜け、2ブロック以上の落下崖は進まない。位置はプレイヤーのAABB（足元）基準で読む。視点制御は tick 毎に誤差の全量を一気に動かさず、減衰ステップ（誤差の45%・上限7°/tick）＋軸別ゲイン適応＋端数ピクセルの蓄積で滑らかに追従し、移動中は照準点を低域通過させて視点と進路がふらつかないようにしている。
- **水中ガード**: 上方向（最大16セル）に水があるブロック（海底の土や、その下に埋もれた土）は対象から外す（泳げないため追うと溺死ループになる。湖の下の乾いた洞窟なども安全側に倒して外れる）。設定 `skip_underwater`（既定 true）で切替可。
- **溺死セーフティネット**: 作業中（移動・採掘・回収・ツール待ち）に頭が水没した状態が続くと、対象を諦めてジャンプ長押しで浮上し、頭が水から出たら探索を再開する。脱出した場所の周囲（半径6）はハザードゾーンとして以降の対象選定から外れるので、岸壁沿いを脱出→再選択で延々と辿ることもない。対象選定をすり抜けた水中スタンドポイントでも溺れないための最終防衛線。
- **経路表示**: 移動・採掘中、緑の軌跡ラインと対象ブロックの黄色い枠をワールド内に描く（SDK の `NativeOutlineRenderer`）。経路探索が有効な間は探索した実ルートを、無い場合は足元から対象への地形沿いラインを描く。`/mine path` で切替、設定 `show_path` でも指定可。
- **経路探索（A*）**: 対象への移動は歩行可能セルを A* 探索した実ルートを辿る（歩行・1段登り・最大3段の落下・掘削セルは高コストで最後の手段）。水セルは通らないので水域は迂回する。ルートが無い場合は従来の直進ナビ（崖ガード・掘り抜け付き）にフォールバック。ルート追従は pure-pursuit 方式（約1.7ブロック先の先読み点へ進み、通過判定は投影ベース、背後に出たウェイポイントはスキップ）で、急な方向転換では前進を止めてその場で旋回するため、行き過ぎて大回りで戻る「ぐるぐる」が起きない。再計画に失敗しても追従中のルートは保持し、開始セルが袋小路扱いの場合は隣接セルから探索を開始する。スタック時はまずジャンプ＋横移動で脱出を試み、それでも駄目なら再計画する。
- **橋渡し（ブリッジ）**: 経路探索は、床が抜けているが足場ブロックを置けるセルを「橋セル」として扱う（徒歩より高く掘削より低いコスト、横方向のアンカーから最大3マス幅まで連鎖して計画）。ホットバーに余りブロック（丸石・土・石など、砂利や砂などの落下ブロックと板材は除く）がある場合のみ有効。追従側は橋セルの手前で立ち止まり、遠い側から順に足場を置いて埋まったことを確認してから渡る。射程外の場合は床の有無を確認しながら縁まで慎重に近づき、最後の1マスはジャンプしながら真下に置く。置けない・届かない場合はその橋を諦めて迂回路に組み直す。
- **水泳**: 陸ルートが無い対象へは水面を泳いで渡る。移動は頭が水面に出ている時だけ進み、頭が沈んだらまず浮上を優先する。張り出し（天井）の下に潜り込んだ場合は、上昇しながら後退して抜ける（実証中に実際に溺れかけた罠への対策）。岸に着いたら陸から再計画する。採掘・回収中は水面に留まるようジャンプを保持し、水中の足場で固まる場面には溺死セーフティネット（Escape）が引き続き効く。
- **採掘**: 対象を向いて攻撃ボタンを押し続け、ブロックが消えたらドロップ回収に1歩進む。
- **AutoTool**: ブロック種別（ツルハシ/斧/シャベル/クワ/ハサミ）と必要素材ランクから、ホットバー内の最適ツールを自動選択する。ダイヤ鉱石に木のツルハシ、のような無駄掘りはしない。
- **AutoCraft（実クラフト）**: 使えるツールがインベントリに無い場合、SDK の `NativeItemStackRequests` アダプタで実際にクラフトする。レシピ表はサーバーから届く CraftingData をそのまま使い（レシピID・生成物の記述子を転記）、本物のクライアントの手作業フロー（グリッドへ配置→`craft_recipe`→結果をカーソルから全量しまう）を ItemStackRequest パケットで再現する（`craft_recipe_auto` は自前BDSが切断してくるため使わない）。ツルハシ用チェーンは「板材→棒→作業台→設置→木のツルハシ→丸石を3つ採掘→石のツルハシ」まで全自動で、丸石集めで作業台から離れた場合は手持ちの作業台をその場に置く（無ければ板材4枚で新規に作る）。グリッドへの配置は画面（インベントリ等）が開いていないとサーバーが拒否する（status 49）ため、チェーン側で画面の開閉も行う。なお自作リクエストへの応答はクライアント自身のインベントリモデルに反映されないため、アダプタが応答から追跡したスナップショットを正として持ち物を読む。材料不足やクラフト失敗時は従来どおり手順をチャットで伝えて待機し、ツールが現れたら自動で再開する。
- **戦闘**: 作業中に敵対Mobが近づくと（水平・垂直とも近接、または至近距離）中断して応戦し、倒したら作業に復帰する。Mob種別はアクターの型コンポーネントから判定する（1.26.60.5実機で召喚検証したID: ゾンビ199456・スケルトン1116962・クモ264995・クリーパー2849、ほかゾンビ系2種）。剣 > 斧の優先でホットバーから最適武器を選び、リーチ（目線からMobのAABBまで約3ブロック）と視線（ボクセルレイキャストで遮蔽チェック）が通った時だけ攻撃する。クリーパーには弓があれば距離を取って射撃し（引き絞りは右ボタンのフィード経路）、弓が無い場合は一撃ごとに後退して爆発を回避する。武器が何も無い相手がクリーパーなら逃げる。届かない相手（高所・水底など）は一定時間で諦めて1分間無視するので、戦闘と浮上のループにはならない。`/mine mobs` で周囲アクターの読み取り値をログに出せる（種別判定のデバッグ用）。
- **ボート**: 長い水の横断（対象まで10ブロック超）でホットバーにボートがあれば、まずボートを水面に出して渡りを試みる（対象ごとに1回だけ）。設置は新規に現れた船体（アクター型90）でのみ確認する（ボートはワールドに残り続けるため、以前の試行の残骸を「今置いた」と誤認しない）。乗船は使用ボタンのパルスで行い、成立の判定は「甲板の高さへのロック」と「船体に密着した状態で漕いでみて船が付いてくるか」の行動プローブの二段構え。乗れたら視点で操舵して対岸近くでスニーク下船する。各段にタイムアウトがあり、失敗したら通常の水泳にフォールバックする。**ボートのクラフト**: ボートを持っていない場合は、岸で AutoCraft により「板材→作業台→設置→ボート」をクラフトしてから渡りを試みる（対象ごとに1回だけ。材料が無ければそのまま泳ぐ）。**乗船について**: 当初は自動テスト環境（BedrockOnLinux/Wine）で使用ボタンのフィード入力が「乗る」判定に届かず乗船が成立しなかったが、2026-11-16 の実証では岸から出艇する形で2回連続で乗船・航行・下船まで成立した（船体がプレイヤーを 5.3 / 3.9 ブロック運んで判定）。長距離では操舵がタイムアウトして途中で下船し、残りを泳いで完走する場合がある。実機Windowsでの挙動は未確認。

## 設定

`Documents/PEXData/AutoMine/config.json`

```json
{ "enabled": true, "radius": 24, "show_path": true, "skip_underwater": true }
```

## 注意

- 採掘中は視点とキー入力をModが占有する。チャットやGUIを開くと（ゲームプレイ非アクティブで）自動的に一時停止する。
- 視点操作にはマウスデバイスの捕捉が必要。参加後に一度でも実マウスを動かせば有効になる（通常のプレイでは自然に満たされる）。
- 縦方向は「届く範囲＋掘り抜け」が中心で、深い縦穴を掘り進む階段掘りは未対応。
